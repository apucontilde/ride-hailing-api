### [fare]
- Offer fare renders the API's **cents**, never whole dollars: `formatMoney(_ride!.totalFare!, currency: _ride!.fareCurrency)` replaces the old `toStringAsFixed(0)` — `driver_app/lib/features/rides/presentation/offer_sheet.dart:178-181`; the single shared convention is `shared/lib/src/utils/money.dart:12` (exactly two decimals; the API `fare_currency` is used as a prefix when present and **never invented**). This currency-honesty holds on every money surface, including the earnings **aggregate** card (bug #13 resolved — see `[history]`).
- Trip-completion breakdown adds the currency to every leg, a `climb +x%` note on the distance leg only when `grade_uplift_pct != 0`, and a `Conditions multiplier ×N.NN` line only when `surge_multiplier > 0`; total is the API `total_fare`. **No fuel line** (fuel is absorbed into the per-km rate server-side). A null fare keeps the `—` placeholder, never a fabricated `0.00` — `driver_app/lib/features/trip/presentation/trip_screen.dart:486-520` (`_fareRow`/`_lineRow` `:660-677`).
- Both wire shapes parse the new fields: shared model `fareCurrency`/`gradeUpliftPct` — `shared/lib/src/models/ride.dart:24,28,89-90`; WS `RideUpdate` nested-`fare` parse + patch merge — `driver_app/lib/core/ride/ride_update.dart:34-35,75-76,100-101`.
- Completion shows the **final** charge only. The API recomputes the actual from stored distance/duration against the **booked** card + booked conditions, **uncapped**, and overwrites the plain money columns (`api_plans/STATUS.md` → Landed `[fare]`); the app's history tile renders `formatMoney(ride.totalFare!, currency: ride.fareCurrency)` — `driver_app/lib/features/rides/presentation/rides_history_screen.dart:236` — and earnings sum only completed rides' final `totalFare` (`history_provider.dart:223-276`) and the aggregate card renders through `formatMoney` with the sole agreed currency (bug #13 resolved — see `[history]`). WS/REST completion merges replace the held booked quote with the final (`ride_update.dart:74,99`).
- Tests: `test/core/ride/ride_update_test.dart` (4: nested-fare parse, final-over-booked merge, no-fare retention/no-fabrication); `test/features/rides/presentation/offer_sheet_test.dart` (`12.40`, `USD12.40`, null `-`); `test/features/trip/presentation/trip_screen_test.dart` (currency/climb/conditions lines + final-only over booked, WS **and** REST); `test/features/trip/providers/trip_notifier_test.dart` (completion adopts final over booked); `test/features/rides/providers/history_provider_test.dart` (refresh replaces booked with final; earnings sum the completed final, not an open stake); `test/features/rides/presentation/rides_history_screen_test.dart` (`USD13.20`, not `USD13.00`).
- **Policy (do not re-litigate):** uncapped actual **replaces** the booked quote; the final is the **only** charge shown — no quoted-vs-charged line, no ± tolerance. The quote survives server-side as `quoted_*` audit columns hidden from JSON (`json:"-"`). The plan's item-3 conditional "show both **if** the API exposes the quote" is **superseded**: the API deliberately exposes no quote, so the app never shows both.
